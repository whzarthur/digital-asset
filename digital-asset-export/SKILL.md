# 数字资产

## 输出边界

这个技能只生成图片。不得创建或导出 HTML 页面、资产管理模板、JSON、CSV、Markdown 文档、PDF、ZIP、数据库、版本报告或视频，也不启动本地预览服务。

根据用户提供的剧本、故事板、角色设定或参考图提取人物、场景和物品。信息足够时先生成概念图，不得直接跳到正式资产；缺少会改变人物身份或整体画风的关键条件时，只询问一个必要问题。按人物 → 场景 → 物品的顺序逐项生成；即使用户要求批量生成，也不得连续生成多个尚未确认的资产。

所有图片都不得带标题、编号、说明文字、分隔标签、平台标记或水印。资产编号只用于文件名，不写入画面。

## 概念图确认门槛

每个资产单元在生成正式资产前，默认先生成三张独立概念图供用户比较；用户指定数量时按其要求。三张方案必须在保留剧本、分镜和已确认项目锚点的前提下形成有意义的设计差异，不得只改变随机背景、轻微色温或无关细节。

- 人物概念图：用单人物全身或 3/4 全身设计图探索五官、发型、体型、服装、配饰和气质；概念图不是三视图或四视图。
- 场景概念图：用一个具有代表性的无人视角探索空间结构、固定陈设、材质、光线和氛围；不得用带人物、箭头或文字的调度图代替。
- 物品概念图：用完整物品的清晰主视角探索轮廓、比例、材质、颜色和关键结构；不出现人物或手部。

概念方案各自作为独立图片生成，不拼成一张带分隔线的方案板；在回复文字中用“概念 A / B / C”区分，图片内部不写方案字母。展示全部概念图后必须停止，询问用户选定哪一张，或需要如何调整；未得到明确选择前不得生成正式资产。

用户要求混合多个方案时，先据此生成新的合并概念图并再次确认，不直接进入正式资产。确认后的概念图成为当前资产的设计基准；正式资产只展开标准视角、细节和版式，不得擅自改变已确认的身份、结构、造型、材质或主色。概念图不计入正式资产张数，不同步到工作台，也不写入正式 `payload.assets` 或 `files`。

## 灵创工作台 MCP

用户提到灵创工作台、工作台项目、MCP、工作台中的分镜或要求把结果同步回工作台时，读取并遵循 [灵创工作台 MCP 接入](references/workbench-mcp.md)。本 Skill 的固定 stage 是 `assets`。

每次工作台任务都必须先调用 `get_stage_contract`，再调用 `read_stage_input`；不得把本 Skill 中的字段示例当作固定 schema。当前资产先完成概念图选择，再生成正式图片。正式图片完成后，必须展示该项的全部正式图片并明确询问“是否确认该正式资产并立即同步到工作台？”。用户肯定答复只授权当前这一项正式资产写入；随即使用 `begin_stage_upload`、`validate_stage_output` 和 `write_stage_output` 完成同步，回读确认成功后才开始下一项。工作台暂时不可用时可以依据用户直接提供的素材独立生成图片，但不得声称已经读取或同步工作台。

工作台资产成果须同时区分镜头的资产需求与实际使用版本：实时契约支持 `payload.requirements` 时，按已确认分镜登记可证实的镜头需求，再以 `usage_bindings` 固定实际采用的图片。已有需求不得因本次只制作一个资产而丢失；具体字段及回读检查见接入参考。

工作台模式必须先读取实际分镜图的图像内容，再询问用户最终资产采用哪种风格；未得到风格选择前不生成图片。分镜图的草图画法不自动等于最终画风。场景主视图或镜头关键帧可继承分镜构图；人物视图板和物品标准图只继承可见设计信息，仍保持本 Skill 规定的中性资产版式。

## 单项双确认与同步

一次确认只对应一个完整资产单元：

- 人物：一个人物身份的一个独立造型状态，包含规定的两张人物图片。
- 场景：一个物理场景的一个环境状态，包含本轮所需的全部独立视角图。
- 物品：一个物品的一个剧情状态，包含主图和本轮确有需要的细节图。

每个资产单元有两个不可合并的确认点：

1. 概念确认：展示当前单元的全部概念方案，用户选定或确认一个方案后，才生成正式资产。概念确认不构成工作台写入授权。
2. 正式确认：展示基于已确认概念生成的全部正式图片，用户确认“该正式资产并同步”后，立即同步当前正式资产；同步成功并回读一致后，用一句话报告当前资产已同步，然后继续下一个资产。

用户在任一阶段要求修改时，只修改当前资产并重新取得该阶段确认。若正式资产修改涉及人物身份、场景结构、物品造型或其他已锁定设计，应退回概念阶段重新确认，而不是绕过概念基准直接重做正式图。未完成正式同步前不得开始下一资产。

不得把多个人物、多个场景或多个物品积攒到最后一次性确认或一次性写入。同步失败时停留在当前资产，修复并重试当前同步；除非用户明确要求跳过，否则不得绕过失败继续生成下一项。独立模式没有工作台项目时仍逐项确认，但确认后只能继续下一项，不能声称已同步。

## 人物资产

每个人物的身份基准以及每个需要独立管理的服装或造型状态，正式资产固定交付两张图片，不多不少：第一张是全身视图板，第二张是人物特写图。前置概念图不计入这两张正式图片。不得把全身视图和人物特写全部塞进一张图，也不得把人物特写拆成第三张图片。

先判断人物视觉风格：

- 写实风格：真人摄影感、电影真人感、照片级写实或以可信真实人类为目标的写实 3D。
- 非写实风格：动画、漫画、插画、二次元、卡通 3D、黏土、绘本、国风绘画、游戏概念设计及其他明显风格化表现。
- 用户未明确说明时，优先依据参考图或项目整体画风判断；仍无法判断且会改变交付结构时，只询问“人物采用写实风格还是非写实风格”。

### 写实风格：两张图

1. 全身四视图：一张拼接图，从左到右严格排列全身正面、全身 3/4、全身侧面、全身背面。
2. 脸部双特写：一张拼接图，左侧为脸部正面特写，右侧为脸部 3/4 特写。两个脸部角度必须合并在这一张图中，不得分别输出两张特写。

建议文件名：

```text
项目ID_CHR_C001_状态_REALISTIC_FULLBODY_4VIEW_v001.png
项目ID_CHR_C001_状态_REALISTIC_FACE_2VIEW_CLOSEUP_v001.png
```

### 非写实风格：两张图

1. 全身三视图：一张拼接图，从左到右严格排列全身正面、全身侧面、全身背面。
2. 人物特写：一张只包含一个人物角度的独立特写图。默认使用最能识别人物设计的头肩或胸像 3/4 特写；用户指定角度或景别时按其要求执行。

建议文件名：

```text
项目ID_CHR_C001_状态_STYLIZED_FULLBODY_3VIEW_v001.png
项目ID_CHR_C001_状态_STYLIZED_CHARACTER_CLOSEUP_v001.png
```

### 两种风格的共同要求

- 固定生成顺序：先生成全身视图板，再把已确定的人物身份作为参考生成第二张特写图。
- 两张图必须属于同一人物、同一造型状态和同一版本，并作为两个独立图片文件交付。
- 全身人物从头到脚完整可见，不裁切头顶、手、脚或服装边缘；各视图统一身高比例、头顶线、脚底线、机位高度、焦段观感和人物占画比例。
- 保持同一五官、脸型、发型、体型、肤色、服装、鞋履、配饰及不可变化特征。
- 使用中性站姿和中性表情，不加入叙事动作、手持道具或场景元素。
- 使用中性浅灰或灰白无缝背景、柔和均匀光线；各视图和特写之间不得出现身份、造型或光色漂移。
- 特写清晰展示眼睛、眉形、鼻形、唇形、耳部、发际线以及人物独有面部锚点；不使用景深遮挡、强烈轮廓光、夸张妆效或会改变五官判断的表情。
- 拼接图内部不写角度标签、标题、编号或说明文字，依靠固定顺序识别视角。

同一人物出现明显不同的服装、发型、年龄阶段或可见伤势时，为该造型状态重新生成完整的两张图；单纯表情变化不新建全套人物资产。

## 场景资产

### 资产边界

- 标准场景资产只包含无人空景，不出现演员、人群、人形剪影、镜中人物、人物占位符、路线、箭头、机位图标、编号或说明文字。
- 场景中的固定家具和固定陈设可以保留；只属于某个镜头的临时人物、手持物和动作状态不得进入场景资产。
- 场景调度图、人物站位图和写实关键帧都不是场景资产。用户明确要求时可以分别生成图片，但不得计入场景资产张数或冒充无人空景。
- 场景调度图主要用于规划、沟通或生成写实关键帧。普通图生视频模型未明确支持布局控制图时，不把带箭头和文字的调度图当作画面参考直接输入；先把调度结果转成无标记的写实首帧、关键帧或终帧。

### 交付层级与张数

根据用户的实际镜头需求选择最小充分集合，不把五张套组强加给所有简单场景：

1. 单向简单场景：默认生成一张能够说明空间关系的主视图。
2. 主反打场景：生成主视图和反向视图；只要摄影机可能转向主视图背后的空间，就必须补反向视图。
3. 用户明确要求“标准场景资产”“完整场景资产”“全方位场景”“多机位测试”“场景一致性测试”或需要人物跨区域走位时，固定交付五张独立的无人空景图：
   - 主视图：从主要入口或叙事起点看向场景核心。
   - 反向视图：与主视图近似相反方向，补足主视图背后的空间。
   - 向东视图：摄影机光轴朝场景东侧。
   - 向西视图：摄影机光轴朝场景西侧。
   - 正俯视图：垂直俯拍完整平面，固定北方朝上。
4. 门后空间、相邻房间、楼梯转角或被固定结构遮挡的区域只有在故事板实际会进入或拍摄时才增补独立视图，不为追求数量生成无用角度。
5. 白天、夜晚、雨天、停电、破损等可见环境变化属于不同场景状态。每个状态分别建立完整所需视图，不在同一张标准图中混合多个状态。

### 坐标与视角规则

- 生成多视图前先确定场景北向和稳定锚点；正俯视图必须北向朝上。若用户指定主视图朝北，则主视图的摄影机位于场景南侧、光轴朝北，反向视图光轴朝南。
- `LOOK_N`、`LOOK_S`、`LOOK_E`、`LOOK_W`一律表示摄影机光轴朝向，不表示摄影机所在方位。禁止使用含义不明确的“东侧图”“西侧图”作为唯一命名依据。
- 四个平视方向应使用可比较的眼平高度、透视关系和焦段观感；故事板明确要求特殊机位或镜头时除外。
- 正俯视图只表达真实空间布局，不使用透视鸟瞰代替，不添加调度标记。

### 跨视图一致性

- 同一 `LOC`、同一状态和同一版本的建筑结构、门窗位置、家具布局、固定陈设、材质、时间、天气、主光方向和色温必须稳定。
- 先确定场景的结构锚点，例如入口、窗户、前台、楼梯、电梯和大型固定家具，再生成其余方向；不得为了构图方便交换、复制、删除或移动锚点。
- 每张图片只表现一个明确视角，不把主视图、反向视图和俯视图拼成一张带标签的视图板。
- 画幅、视觉风格和时代环境跟随项目或故事板；无依据时不擅自添加醒目标志、文字招牌或剧情信息。
- 视频生成时只选择当前镜头真正需要的场景视图，不要求一次上传整套五张。俯视图默认用于空间规划；只有目标模型明确支持布局或控制参考时才作为直接输入。

### 场景资产命名

文件名统一使用：

```text
项目ID_LOC_场景编号_状态_视角_版本.png
```

字段规则：

- `项目ID`：项目的稳定英文或数字短标识。
- `LOC`：场景资产类别固定代码。
- `场景编号`：同一物理场景固定使用 `L001`、`L002` 等编号；换拍摄方向不新建场景编号。
- `状态`：使用 `DAY`、`NIGHT`、`RAIN`、`DAMAGED` 等简洁大写英文；同一套图状态完全一致。
- `视角`：必须包含镜头朝向或俯视朝向，避免只写含义不明的方位名称。
- `版本`：使用 `v001`、`v002` 递增；重做不得覆盖已经交付的旧版本。

五张标准场景资产建议命名：

```text
项目ID_LOC_L001_DAY_MAIN_LOOK_N_v001.png
项目ID_LOC_L001_DAY_REVERSE_LOOK_S_v001.png
项目ID_LOC_L001_DAY_SIDE_LOOK_E_v001.png
项目ID_LOC_L001_DAY_SIDE_LOOK_W_v001.png
项目ID_LOC_L001_DAY_TOPDOWN_N_UP_v001.png
```

如果主视图不是朝北，按实际光轴方向替换 `LOOK_N`，反向视图使用相反方向。`MAIN`、`REVERSE`、`SIDE`表示视图用途，`LOOK_*`才是无歧义的观看方向。

非场景资产的辅助图片使用独立类别代码，不使用 `LOC`：

```text
项目ID_BLK_L001_状态_SHOT_S001_v001.png
项目ID_SHOT_S001_KF_START_v001.png
项目ID_SHOT_S001_KF_MID_v001.png
项目ID_SHOT_S001_KF_END_v001.png
```

- `BLK`：带人物路线、机位、箭头或说明的调度图。
- `SHOT ... KF_*`：包含人物的写实镜头关键帧。

## 物品资产

- 使用中性浅灰或灰白背景，完整展示轮廓、材质、颜色、比例和关键细节。
- 不出现人物、手部或使用动作；必须说明握持方式时另生成细节参考图，不污染标准主图。
- 有打开/关闭、完整/破损、亮灯/熄灭等剧情状态时，每个状态独立生成，不能在同一张标准图里混合多个状态。
- 同一物品各状态保持设计、尺寸、材质、磨损、标记位置和颜色一致。

建议文件名：

```text
项目ID_PRP_P001_状态_MAIN_v001.png
项目ID_PRP_P001_状态_DETAIL_v001.png
```

## 一致性与迭代

- 新资产以用户刚确认的概念图为首要设计基准；正式资产必须延续其中的身份、结构、造型、材质和主色。
- 优先使用用户提供的已确认参考图。修改现有资产时，以最近一次明确认可的图片为身份和风格基准。
- 将镜头中的服装、伤势、湿润程度、物品开合等视为状态，不误判为新人物或新物品。
- 重做某一张时只改用户指出的内容，保持其他身份锚点、画风、光线和造型不变。
- 生成完成后直接交付图片，并用一句话说明对应资产、状态和视角；不附带资产页面、清单或额外方法论文档。
- 不主动建议 LoRA、模型训练、接口集成或视频生成。
